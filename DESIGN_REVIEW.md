# Recruitment presentation — design revision

The audience is a school recruiter, not a software developer. The presentation
supports Igor's spoken introduction and should make the meaning of each example
apparent without requiring the audience to read a software manual.

## References consulted

- Nancy Duarte, *slide:ology*: arrangement, hierarchy, contrast, proximity and whitespace.
  [Author's book page](https://www.duarte.com/resources/books/slideology/)
  and [practical Glance Test guidance](https://www.duarte.com/blog/perfect-your-slide-design/).
- Garr Reynolds, *Presentation Zen*: meaningful emphasis, alignment and removal of nonessential elements.
  [Author's sample chapter](https://www.presentationzen.com/chapter6_spread.pdf)
  and [author's signal-to-noise exercise](https://presentationzen.com/blog/the-signal-to-noise-ratio-activity).
- Richard E. Mayer and Logan Fiorella: coherence, signaling, redundancy and contiguity.
  [Cambridge Handbook chapter summary](https://doi.org/10.1017/9781108894333.019).

These references guide design decisions; they do not establish that a particular
render has passed a human readability or comprehension test.

## Applied changes

| Area | Decision |
| --- | --- |
| Hierarchy | Age appears once as neutral metadata beside the name. Emphasis belongs to the person, the current message and project evidence. |
| Focus | Each hold supports one part of the spoken explanation. A message title replaces the repeated name, section title, subtitle, rule and footer stack. |
| Evidence | FT examples occupy the main canvas. Kalwer is cropped around its useful interface rather than desktop wallpaper. Phonomenal uses a focused recorder view. |
| Relationships | vctts and Phonomenal have aligned, adjacent role descriptions. The reader need not infer their different purposes from unrelated screenshots. |
| Typography | Fixed sans-serif hierarchy, explicit authored line breaks, common alignment and safe margins. No shrinking text to resolve overflow. |
| Restraint | Remove repeated branding, slide counters and source footers from the audience. Source provenance remains available in the asset manifest. |
| Wording | Use function names and implementation details: GUI/TUI/WWW backends, GTK3/Cairo rendering, audio outputs and vcpack preparation. Remove slogans and repeated personal commentary from all three scripts and detours. |
| Spoken delivery | Full text stays in the private reader. The audience sees short statements and evidence rather than a transcript. |
